# Pipeline Version 4: Observation to Design

Use this sequence when a concrete property of the task motivates the contribution.

1. State the proposed change.
2. Explain the observation that motivates it.
3. Derive the relevant design decision from that observation.
4. Describe the resulting operation.
5. Identify the evidence needed to test the expected advantage.

In the local Deep Snake example, a contour's closed connectivity provides the explanatory link between the representation and the chosen processing operation. The teaching value is the visible reasoning chain from structure to design.

```latex
% Observation: [property of the data or task]
% Implication: [what this property permits or requires]
% Design: [operation that implements the implication]
% Test: [comparison that distinguishes the proposed mechanism]
```

An intuitive observation motivates a method; it does not replace empirical evidence for its benefit. Teaching-source links are recorded in the [example bank index](../index.md).
